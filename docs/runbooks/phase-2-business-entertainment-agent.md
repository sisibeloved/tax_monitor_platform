# 阶段2业务招待费Agent运行手册

## 1. 适用范围

本手册用于业务招待费月度监测的版本发布、任务运行、异常处置、黄金数据维护、回滚和审计。当前数据入口是受控CSV/XLSX文件；切换为SAP、合思或OA接口时，只替换采集适配器，不改变快照、证据、判断和案件契约。

平台不会根据金额、日期或人员相似度自动挂接单据。没有精确前置单据ID的SAP凭证只形成覆盖观察，不进入Agent语义判断。

## 2. 运行前检查

每月运行前必须确认：

1. 业务招待费公司清单为已审批、已发布版本，且本月只命中一个有效版本。
2. 五类数据均通过采集批次质量门禁：SAP费用凭证、合思业务招待报销、OA业务招待申请、OA自采报销和OA物料领用。
3. SnapshotSet状态为`PUBLISHED`且发布时间不为空；`DRAFT`或`VALIDATED`均不得运行。
4. 规则、候选词库、模型、提示词、案例库和建议科目字典均使用已发布版本ID。
5. 企业模型端点使用HTTPS，凭据仅以外部引用配置，零留存要求为开启状态。配置不完整时服务必须拒绝启动或拒绝调用，不得回退到伪客户端。
6. Worker收到的参数只能是运行ID、公司编码、月末、SnapshotSet ID和上述受控版本ID，不得传输原始业务文本。

## 3. 版本发布

公司清单、建议科目字典、模型、提示词和案例库均执行“上传—独立复核—批准—发布”。上传人、复核人不得为同一人员。发布后版本内容不可修改；需要调整时创建新版本并重新审批。

发布顺序建议为：建议科目字典、案例库、提示词、模型、规则与候选词库。调度请求应一次性冻结全部版本ID，重试继续使用原ID和原幂等键。

## 4. 企业模型与隐私

- 不在配置文件、运行手册、日志或数据库审计字段中保存模型令牌。
- 模型凭据由部署环境的密钥服务按`semantic_model_credential_ref`解析。
- 内置Worker组合把`semantic_model_credential_ref`作为注入环境变量名读取；如果生产环境使用密钥服务URI，部署时必须替换凭据解析器，不得把令牌写入该配置项。
- 请求只发送获准字段；姓名、电话号码和身份证件号码在调用前脱敏。
- 模型请求不包含工具定义，来源文本中的“忽略规则”“调用工具”等内容只作为证据文本处理。
- 企业端点必须返回零留存确认；缺失确认时本次结果作废并记录阻断审计。
- 审计只保存请求/输出校验和、允许字段名、版本、耗时、token数量、schema状态、重试和留存确认，不保存原始业务文本。

## 5. 月度流水线

固定执行顺序如下：

1. 解析已发布公司范围。
2. 加载已发布SnapshotSet及公司快照。
3. 执行精确证据关联，并将金额/日期相似关系保留为`FUZZY`提示。
4. 写入SAP覆盖观察；独立SAP到此停止。
5. 对SAP已关联和业务单据未关联两种模式生成高召回候选。
6. 使用已发布制品调用受治理Agent，并进行独立证据与科目复核。
7. 由服务端路由为检测记录、补证任务或风险案件。

任一步失败不得跳过质量门禁。公司级失败相互隔离；可重试错误继续使用同一SnapshotSet和版本集合。

## 6. 异常处置

### 6.1 schema失败

结构化模型响应不符合schema、缺少零留存确认或引用无效证据时，不创建权威检测。记录调用审计并进入失败/补证处理，不允许人工直接修改模型原响应后入库。

### 6.2 公司重跑

确认原运行ID、公司、期间、SnapshotSet和全部版本ID未变化后重投公司任务。相同输入会生成相同幂等键；如果需要使用新数据或新版本，应新建运行，不得覆盖原运行。

### 6.3 待定位SAP凭证

业务单据未关联风险可以正式进入清单，金额取合思或OA规范单据。解决时只能选择已持久化的`EXACT`证据关系，并提交案件行版本。服务端会在同一事务中重新校验公司、来源、目标和快照；行版本冲突返回409，应刷新后复核。

### 6.4 覆盖结果解读

- `EXACT_LINKED`：已通过精确单据ID建立证据关系，可由规范业务单据进入Agent判断。
- `FUZZY`：只有金额、日期或人员相似，不得自动挂接。
- `UNLINKED`：未找到精确前置单据，只形成SAP覆盖观察，不进入Agent判断。

## 7. 黄金数据与发布指标

黄金数据每条样本必须包含脱敏输入、来源模式、预期证据、财务标签、税务标签、不同的两名标注人、独立裁决人、审批状态、冻结版本、记录校验和、版本校验和及冻结时间。

刷新流程：新增样本、财务标注、税务标注、分歧裁决、审批、计算记录校验和、冻结版本、运行离线指标。冻结后不得直接修改；需要修订时创建新冻结版本。

发布门槛为：候选试点召回率不低于90%，模型和证据复核后的发布召回率不低于95%，高置信度准确率不低于80%，已知案例漏检数为0。指标分别按`SAP_LINKED`和`BUSINESS_DOCUMENT_UNLINKED`计算，并包含不应预警的负样本。

## 8. 清单、导出和KPI口径

解决后的来源案件保留审计记录，并通过`merged_into_case_id`指向SAP根案件。风险清单、驾驶舱、Excel导出和KPI统一只查询`merged_into_case_id IS NULL`的根案件，因此一次风险只统计一个案件和一笔金额。

Excel文本对`= + - @`开头值进行公式转义。阶段4异步导出必须复用阶段2的根案件查询和版本化列定义。

## 9. 回滚

1. 停止新月度任务并记录受影响的运行ID。
2. 将有问题的模型、提示词、案例库、规则或科目字典版本退役；不要修改已发布内容。
3. 恢复上一个已审批版本集合并创建新运行。
4. 已生成的检测、补证任务、案件、合并历史和调用审计保持不变，用于追溯。
5. 数据库迁移回滚仅在变更窗口执行，并先验证当前唯一迁移头及备份；不得用回滚删除业务审计记录。
