# 回滚与恢复操作手册

## 触发条件和负责人

出现签名验证失败、不兼容模型或规则配置、迁移异常、跨公司隔离风险、批次重复或错误结果时，值班运维负责人立即停止晋级。集团税务负责人决定业务结果是否撤回，安全负责人处理权限或签名事件，数据负责人确认恢复数据一致性。生产操作必须关联已批准变更号，申请人与批准人不得相同。

## 先演练、后生产

本地验收演练先执行：

```bash
make verify-release
make verify-rollback
```

该命令仅恢复到名称以 `isolated-` 开头的隔离目标，不修改在线数据库。证据写入：

- `artifacts/acceptance/phase-4/rollback-checkpoint-*.json`：可续跑检查点；
- `artifacts/acceptance/phase-4/rollback-report.json`：最终恢复报告；
- 不可变审计账本：请求、批准、每个检查点、失败/续跑、清单切换、校验和、代表公司重跑和恢复决定。

## 固定执行顺序

1. 验证候选清单和上一清单的签名、摘要及密钥状态。
2. 阻止新任务，排空或安全撤销执行中任务，并记录受影响批次。
3. 撤销相关导出下载能力，下载时仍必须重新授权。
4. 将指定备份恢复到隔离目标，禁止直接覆盖在线数据库。
5. 仅在隔离恢复副本上验证迁移降级和重新升级。
6. 部署上一份已验证清单。
7. 比较源数据、快照、风险事项和关键金额校验和。
8. 重跑一家代表性公司，确认稳定指纹和零重复风险敞口。
9. 由运维负责人记录恢复或继续遏制决定。

脚本对每一步写入输入摘要、终态和证据摘要。相同输入再次执行时会验证已完成证据并从首个未完成步骤继续，不会重复恢复、撤销、部署或创建风险事项。更改备份、清单、批次、批准号或目标后不得复用旧检查点。

## 试点和生产防护

试点或生产模式只接受 `PRODUCTION_KMS_HSM` 签名清单，并要求：

```bash
export ROLLBACK_OPERATION_MODE=APPROVED
export ROLLBACK_CONFIRM_CHANGE_ID='CHG-已批准编号'
export ROLLBACK_COMMANDS_JSON='{"PRECHECK_SIGNATURES":["平台命令","参数"],"...": ["..."]}'
```

`ROLLBACK_COMMANDS_JSON` 必须覆盖全部检查点，每条命令采用参数数组而不是 shell 字符串，退出码必须为 0，标准输出必须是 JSON 证据对象。任何缺失、非零退出码、无效 JSON 或校验失败都会停止流程并保留检查点。

## 恢复完成判据

只有签名有效、恢复目标隔离、迁移演练通过、校验和相等、代表公司重跑成功、重复风险敞口为零且批准人记录恢复决定时，`recovery_verified` 才能为 `true`。未满足时保持告警和遏制状态，不得把技术失败解释为“无风险”。
