# 签名发布操作手册

## 适用范围

本手册用于试点和生产环境的所得税风险监测平台发布。任何候选版本在晋级前都必须具备冻结重放报告、规范清单、批准记录和可验证的 Ed25519 签名。

## 职责与批准

- 发布执行人：创建候选、运行验证命令并保存证据。
- 集团税务负责人：批准公式、语义指标和业务回放结果。
- 安全负责人：确认公司隔离、模型网关、依赖和签名控制通过。
- 运维负责人：批准部署窗口、备份、恢复点和回滚方案。
- 生产晋级至少需要集团税务负责人和运维负责人分别批准；执行人不得代替批准人。

## 发布前检查

在仓库根目录执行：

```bash
make verify-governance
make security-check
make verify-migrations
make verify-release
make verify-capacity COMPANY_FIXTURE=126
make verify-rollback
make uat SNAPSHOT_SET=pilot-2026q2
```

所有命令必须返回 0。验收制品位于 `artifacts/acceptance/phase-4/`。重点核对：

- `replay-report.json` 中所有门禁通过；
- `capacity-report.json` 的有效公司成功率不低于 98%，且 T+2 通过；
- `migrations.json` 的空库升级和降级重升均通过；
- `rollback-report.json` 的恢复校验通过；
- `uat-scorecard.json` 的 `production_ready` 为 `true`。

## 签名和晋级

本地 `make verify-release` 仅使用单次临时密钥证明签名链路，输出明确标记为 `CI_EPHEMERAL_NOT_FOR_PRODUCTION`，不得作为生产签名。

生产发布必须由受保护工作流获取短期工作负载身份，调用密钥允许清单中的 KMS/HSM Ed25519 密钥。应用进程、工作流日志和制品中都不得出现私钥。签名后必须重新下载清单、签名和公钥版本，重新计算清单摘要并验证，再允许晋级。

密钥轮换时仅信任当前密钥和明确保留、尚未超过重叠截止时间的上一密钥。未知、已退役或超过保留期的密钥一律阻断。

## 失败处理

任一门禁失败时停止晋级，保留候选清单和失败报告，不得把技术失败解释为“无风险”。数据库迁移、模型配置、批次交付或签名验证异常时，按 `rollback.md` 执行回滚演练或生产回滚。

## 发布后验证

发布后检查存活、就绪、队列积压、公司任务终态、数据就绪到输出就绪时间、模型供应商错误和导出失败。抽取一家代表性公司重跑，确认幂等键、风险指纹和金额均未重复。将清单摘要、签名密钥版本、批准人和验证结果写入仅追加发布审计事件。
